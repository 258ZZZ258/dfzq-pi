# 审计报告自动化生成需求文档解析

## 一、需求背景

当前审计报告主要由工作人员基于固定模板、经营数据 Excel、历史审计问题、职能部门反馈材料以及人工判断手动编写。人工报告在格式、章节、字段和表述上具有较强规律性，但涉及多类数据来源、条件段落和审计判断，导致生成周期较长、字段核对成本高、报告一致性依赖个人经验。

本次需求目标是在“审计大模型页面”的报告智能化能力中，建设“审计报告自动化生成”功能，使系统能够基于模板和多源数据自动生成 Word/PDF 报告，并通过人工审核修订，最终让自动生成报告达到人工手写报告约 80%-90% 的一致性。

## 二、建设目标

1. 支持基于报告模板自动生成审计报告 Word/PDF。
2. 支持从系统数据、外部系统、用户上传文件、历史问题库等来源获取报告内容。
3. 对报告中的填数点、删除点、动态内容设置规则和校验机制。
4. 首期报告生成入口以常规审计报告、离任审计报告为核心；反洗钱审计报告、审计征求意见书已有标准模板和人工样本，应纳入模板能力和字段规则预留，是否进入首期开发需业务确认。
5. 支持单个营业部生成和批量生成多个营业部报告。
6. 支持生成后人工预览、修改、确认和下载。

## 三、需求范围

本阶段优先聚焦“报告字段 → 数据来源 → 获取方式 → 生成规则”的梳理和落地，为后续交互设计、接口设计和开发排期提供依据。

经复核，任务文档中明确的首期报告类型为常规审计报告和离任审计报告；两个子文件夹中的标准模板和人工样本还包含反洗钱审计报告、审计征求意见书，以及“监督共享信息汇总分析报告框架”。因此，本文档按以下范围拆分：

1. 首期核心开发范围：常规审计报告、离任审计报告。
2. 模板扩展和字段预留范围：反洗钱审计报告、审计征求意见书。
3. 补充材料来源范围：监督共享信息汇总分析报告框架，用于外部事项、内部事项、监管检查、内部审计整改等信息归集，暂不作为独立报告生成类型。

核心输出物包括：

1. 《审计报告字段数据来源梳理表》
2. 《审计报告自动生成交互设计说明》
3. 《离任审计报告生成规则》
4. 需求确认会议材料

## 四、报告类型解析

### 4.1 常规审计报告

常规审计报告是最核心的基础报告类型，主要包括：

1. 报告头部信息
2. 基本情况
3. 经营情况三张表
4. 内部控制情况
5. 营业部负责人经济责任履行情况
6. 前次审计整改情况
7. 审计发现的主要问题
8. 审计意见及整改要求
9. 落款与报告日期

关键自动化点：

1. 营业部名称、地址、人员数、负责人任职情况自动获取或半自动确认；人员数以人力资源管理总部提供数据为准，无证券经纪人时删除“证券经纪人X名”表述。
2. 经营数据从用户上传 Excel 中解析，并填充财务指标、业绩指标、排名情况。
3. 审计问题从问题库读取，按分类生成问题章节。
4. 整改意见根据问题类型生成建议草稿，但需支持人工调整，不能仅按固定建议库机械匹配。
5. 风险事项、外部检查、重大投诉、合规问责、绩效考核等仍需人工确认或职能部门提供。
6. 章节编号需由模板和实际段落动态生成。标准常规模板为“一、基本情况 / 二、审计发现的主要问题 / 三、审计意见及整改要求”，但部分人工样本存在“前次审计整改情况”后编号显示为“四、审计意见及整改要求”的情况，开发时不能硬编码章节编号，应以最终模板排版规则为准。
7. 经营表数字格式需符合模板批注要求：数字宋体10号字，负数标红。

### 4.2 离任审计报告

离任审计报告是在常规审计报告基础上的增强版本，重点评价负责人任职期间履职情况。

主要增加内容：

1. 离任人员姓名、职务、任职期。
2. 任职和免职发文信息。
3. 任职期间主要职责及履职评价。
4. 任职期内经营情况。
5. 廉洁从业、信访投诉、合规问责、绩效考核情况。
6. 任职期内历次审计问题及整改情况。
7. 离任审计结论。

关键自动化点：

1. 任职期必须以发文为准；人力资源管理总部发文写“公司发布”，财富管理委员会发文写“财富管理委员会发布”，文号需与发布主体保持一致。
2. 历史问题需按“负责人任职期间”筛选。
3. 对重大问题、未整改问题、屡审屡犯问题需重点展示。
4. 廉洁从业和信访投诉属于高风险内容，必须人工确认。
5. 结论语气需根据问题数量、问题严重程度、整改情况动态生成。
6. 离任报告中经营情况应写“其所在营业部”；表格列示最近完整三年及本年序时进度，文字评价覆盖负责人整个任期。若任期未满三年，删除“近三年”字样。

### 4.3 反洗钱审计报告（模板扩展范围）

反洗钱审计报告独立性较强，与常规报告重叠较少，重点关注反洗钱专项工作。该类型已有标准模板和人工样本，但任务文档首期入口未明确将其列为首期报告类型，建议作为扩展范围或配置化模板预留。

主要内容包括：

1. 内控机制建设
2. 客户身份识别
3. 客户风险分类管理
4. 大额交易和可疑交易报告
5. 客户身份资料和交易记录保存
6. 培训与宣传
7. 反洗钱问题清单
8. 审计意见

关键自动化点：

1. 需要对接反洗钱监控系统。
2. 需要判断审计期内是否存在可疑交易报送。
3. 需要判断是否存在客户风险等级划分、定期审核、监管函件录入等问题。
4. 若未发现反洗钱问题，应使用“无问题版”模板。
5. 若发现问题，应使用“有问题版”模板，并保证基本情况与问题描述不矛盾。

### 4.4 审计征求意见书（模板扩展范围）

审计征求意见书可视为常规审计报告的精简版，主要复用常规报告中的基本情况和审计发现问题。标准模板明确“具体要求参见《常规审计报告》”，但它不是简单截取正文，还需要保留整改计划反馈要求、附表字段和落款规则。

主要内容包括：

1. 审计背景和审计期间。
2. 基本情况。
3. 审计发现的主要问题。
4. 整改计划反馈要求。
5. 反馈期限。

自动化重点：

1. 从常规审计报告草稿中引用对应章节。
2. 根据问题清单生成整改计划附表。
3. 默认反馈期限为 3 个工作日。

## 五、核心业务流程

整体流程如下：

1. 用户进入报告生成入口。
2. 选择报告类型。
3. 输入生成条件，包括营业部、审计周期、离任人员等。
4. 系统自动获取基础数据、人员数据、问题数据、整改数据。
5. 用户上传经营数据 Excel 或其他补充材料。
6. 系统解析数据并展示解析结果。
7. 系统识别缺失、冲突、异常字段。
8. 用户补充或确认关键字段。
9. 系统填充报告模板。
10. 生成报告任务。
11. 用户预览 Word/PDF。
12. 用户人工修改确认。
13. 最终下载或归档。

## 六、数据来源解析

### 6.1 系统自动获取类

适合自动获取的数据包括：

1. 营业部基础信息
2. 营业部代码
3. 审计项目信息
4. 审计问题列表
5. 整改跟踪状态
6. 历史审计问题

来源系统包括：

1. 审计系统
2. 基础数据库
3. 问题库
4. 整改跟踪系统

### 6.2 外部系统接口类

需要进一步确认接口可用性的数据包括：

1. OA 发文：负责人任免、机构迁址、更名、设立、撤并等。
2. 人事系统/人力资源管理总部数据：正式员工数、证券经纪人数、人员名单、职务、任职状态。其中报告“截至审计期末”的人员数以人力资源管理总部提供数据为准。
3. 反洗钱监控系统：可疑交易、风险等级审核、监管函件录入。
4. 天眼查：营业部名称和地址交叉核验。

### 6.3 用户上传文件类

当前最关键的上传文件是经营数据 Excel。

该文件用于生成：

1. 财务指标表
2. 业绩指标表
3. 指标排名表
4. 经营情况文字评价

需要标准化的字段包括：

1. 分支机构名称
2. 分支机构代码
3. 指标名称
4. 年度/期间
5. 金额
6. 排名

除经营数据 Excel 外，模板文件夹中的“监督共享信息汇总分析报告框架.xls”可作为补充材料来源或信息归集模板，覆盖监管检查、监管函件、外部审计检查、内部审计检查、合规风险、反洗钱、系统权限、员工执业、财务管理等事项。该文件当前不作为独立报告类型，但其字段可用于补充常规/离任报告中的“外部检查、风险事项、内部审计整改、合规问责”等段落。

### 6.4 人工确认类

下列内容即使可以由系统辅助生成，也建议保留人工确认：

1. 合规问责事项
2. 信访投诉和案件情况
3. 廉洁从业评价
4. 绩效考核结果
5. 监管关注函及整改情况
6. 离任审计结论
7. 问题描述最终表述
8. 重大风险事项
9. 经营情况文字评价和排名区间表述，系统可生成初稿，但需人工确认语气是否符合人工报告风格。

## 七、页面功能解析

### 7.1 报告生成入口

用户需要选择：

1. 报告类型，首期建议仅开放常规审计报告、离任审计报告；反洗钱审计报告和审计征求意见书作为模板扩展项，待范围确认后开放。
2. 营业部
3. 审计周期
4. 离任人员，离任报告需要
5. 生成模式：单文件或批量

### 7.2 数据准备页

展示各类数据准备状态：

1. 基础信息是否已获取
2. 人员信息是否已获取
3. OA 发文是否已匹配
4. 经营数据是否已上传
5. 问题列表是否已获取
6. 整改情况是否已获取
7. 是否存在缺失或冲突

支持操作：

1. 重新获取
2. 上传文件
3. 手工补录
4. 确认使用

### 7.3 文件上传页

支持两种模式：

1. 单个上传：适合单营业部报告。
2. 批量上传：适合一次生成多个营业部报告。

上传后系统需要完成：

1. 文件格式校验
2. 字段结构校验
3. 营业部匹配校验
4. 期间完整性校验
5. 解析结果预览

### 7.4 解析结果页

展示解析出的关键字段，例如：

1. 营业部名称
2. 审计期间
3. 员工数量
4. 负责人
5. 经营指标
6. 指标排名
7. 问题数量
8. 整改状态

异常提示包括：

1. 未找到指定期间经营数据。
2. 营业部名称与系统不一致。
3. 指标缺失。
4. 排名列缺失。
5. OA 发文未匹配。
6. 人员数据冲突。

### 7.5 报告生成任务页

展示任务状态：

1. 待生成
2. 生成中
3. 待人工确认
4. 生成成功
5. 生成失败

批量生成时需展示每个营业部的独立状态和错误原因。

### 7.6 报告预览页

支持：

1. Word/PDF 预览
2. 字段高亮
3. 异常字段提示
4. 人工修改
5. 下载
6. 重新生成
7. 确认归档

## 八、关键生成规则

### 8.1 经营数据生成规则

1. 优先使用营业部代码匹配经营数据。
2. 经营数据金额单位统一为万元。
3. 金额保留两位小数。
4. 大额数字使用千分位。
5. 排名字段显示整数。
6. 指标名称需支持同义词映射。
7. 表格列应根据审计期间和可得经营期间动态生成。
8. 文字评价应根据收入结构、利润正负、趋势变化和排名区间自动生成。
9. 排名区间按标准模板批注采用五档：上游、中上游、中游、中下游、下游。初步规则为按参与排名总家数除以5划分区间，而不是仅分为上游/中游/下游三档。
10. 财务指标表中的负数需在 Word 中标红；数字字体需符合模板要求。

### 8.2 问题描述生成规则

问题描述建议采用三段式：

1. 问题标题
2. 制度依据
3. 问题事实

问题分类应决定章节标题和整改意见匹配。

### 8.3 条件删除规则

需要根据条件删除或替换的内容包括：

1. 无迁址/更名时删除历史变化说明。
2. 无监管函/问责/投诉时删除风险事项段落。
3. 反洗钱无问题时使用无问题版模板。
4. 有可疑交易时使用“有可疑交易”段落，无则使用“无可疑交易”段落。
5. 离任任期未满三年时删除“近三年”字样。
6. 无某类问题时删除对应问题分类和整改建议。
7. 常规报告内部控制六大领域一般需写全；如存在未了结客户投诉，删除“客户投诉处理”表述；如存在员工合规问责，删除“员工执业行为管理”表述，并另起段落说明问责事项。
8. 重大投诉即使已了结，若涉及员工执业、廉洁从业或给公司/营业部造成较大损失，仍需披露。
9. 离任报告如任职期内未做过审计，历次审计问题整改情况段落不写。

### 8.4 校验规则

系统生成报告后至少需要校验：

1. 营业部名称全文一致。
2. 审计期间和经营数据期间一致。
3. 经营表数据与文字评价一致。
4. 问题分类与整改意见一致。
5. 反洗钱基本情况与问题段落不矛盾。
6. 离任结论与历史问题、重大风险事项一致。
7. 报告标题、称呼、落款符合报告类型。
8. 缺失字段必须进入人工确认流程。
9. 章节编号不得硬编码，需在条件段落删除、保留后自动重排；标准常规模板为“三、审计意见及整改要求”，但人工样本中存在编号差异，生成后需做编号连续性校验。
10. 人员数、证券经纪人数、负责人任职历程、发文主体和文号需逐项校验，尤其是“公司发布”和“财富管理委员会发布”的主体一致性。

## 九、自动化可行性分析

### 9.1 高可行性

1. 报告标题和固定文本生成。
2. 营业部名称、代码、审计期间填充。
3. 经营数据三张表填充。
4. 问题清单按分类生成。
5. 整改意见按问题类型生成草稿。
6. 征求意见书从常规报告复用生成，前提是该类型纳入本期范围。

### 9.2 中可行性

1. 负责人任职历程生成。
2. 内部控制情况文字生成。
3. 经营情况趋势评价。
4. 排名区间评价。
5. 离任历史问题筛选。
6. 反洗钱专项段落条件判断，作为扩展模板能力。

### 9.3 低可行性或需人工复核

1. 廉洁从业评价。
2. 信访投诉事件描述。
3. 监管函件影响判断。
4. 合规问责责任归属。
5. 离任审计结论语气。
6. 重大风险事项是否披露。

## 十、待确认问题

1. OA 系统是否开放发文查询接口。
2. 人事系统是否开放按审计期末取数接口。
3. 天眼查是否正式作为名称和地址核验来源。
4. 反洗钱监控系统是否支持自动查询可疑交易、风险等级审核和监管函件录入情况。
5. 经营数据 Excel 是否可以固定为标准模板。
6. 批量生成时经营数据是一个总表还是每个营业部一个文件。
7. 离任报告历史问题筛选规则是否只展示任职期间问题。
8. 已整改普通历史问题是否需要展示。
9. 问题描述是否允许系统全自动生成，还是必须人工审核。
10. 排名区间五档划分是否严格按“总家数除以5”执行，以及边界值如何归档。
11. 哪些段落必须支持人工强制保留或删除。
12. 报告生成后是否需要留痕版本管理。
13. 反洗钱审计报告、审计征求意见书是否纳入首期交付，还是仅做模板预留。
14. 监督共享信息汇总分析报告框架是否需要在数据准备页提供上传和结构化录入入口。

## 十一、优先级建议

### P0

1. 标准化经营数据 Excel 模板。
2. 明确字段数据来源和接口可用性。
3. 完成常规审计报告自动生成主流程。
4. 完成经营三表自动解析和填充。
5. 完成问题库到报告问题章节的映射。

### P1

1. 支持离任审计报告生成。
2. 支持历史问题筛选。
3. 支持数据准备页和解析结果页。
4. 支持报告预览和人工修改。
5. 支持章节编号自动重排、条件段落删除、经营文字评价校验。

### P2

1. 支持批量生成。
2. 支持 Word/PDF 双格式输出。
3. 支持版本留痕。
4. 支持异常字段智能提示。
5. 支持报告一致性评分或自动校验报告。
6. 支持反洗钱报告有问题/无问题分支。
7. 支持审计征求意见书及整改计划附表生成。
8. 支持监督共享信息汇总材料结构化上传。

## 十二、验收标准建议

1. 系统可根据营业部和审计周期生成常规审计报告草稿。
2. 经营数据三张表与上传 Excel 数据一致。
3. 报告中的营业部名称、负责人、审计期间、报告日期无明显错配。
4. 问题章节可按问题库自动生成并保留制度依据和问题事实。
5. 整改意见可根据问题分类生成草稿，并允许人工调整。
6. 离任报告可生成任免职、经营情况、绩效考核、历史问题和审计结论草稿。
7. 缺失或冲突数据能进入人工确认流程。
8. 章节编号、落款主体、人员数来源、发文主体、经营表负数标红等格式和口径通过校验。
9. 单个常规/离任报告生成后经人工少量修改可达到人工报告 80%-90% 的一致性。
10. 若扩展范围纳入反洗钱报告，则反洗钱报告需能根据是否存在问题选择有问题版/无问题版模板，并保证基本情况与问题段落不矛盾。

## 十三、结论

审计报告自动化生成具备较明确的模板基础和字段规律，尤其是常规审计报告和经营数据表格部分，自动化可行性较高。要达到人工报告 80%-90% 的一致性，关键不在单纯文本生成，而在于数据源标准化、问题库结构化、条件段落规则化和人工确认流程产品化。

建议项目下一步优先推进三件事：

1. 固定经营数据 Excel 模板和字段映射。
2. 确认 OA、人事、反洗钱系统接口或上传替代方案。
3. 基于《审计报告字段数据来源梳理表》设计数据准备页、解析结果页和报告预览页。

## 十四、本次复核修订结论

复核两个子文件夹中的标准模板、批注版、人工报告和 Excel 框架后，原需求解析文档总体方向正确，但存在几处需要修订后才能作为开发依据的口径问题：

1. 范围口径：任务文档首期入口只明确常规审计报告和离任审计报告；反洗钱审计报告、审计征求意见书虽有模板和样本，但应标为扩展范围或待确认范围。
2. 数据口径：人员数应明确以人力资源管理总部提供数据为准；发文主体需区分公司/人力资源管理总部与财富管理委员会。
3. 经营数据口径：排名区间应按五档划分；负数需标红；文字评价不能只按三档粗略生成。
4. 条件段落口径：内部控制六大领域、重大投诉、合规问责、离任历次审计问题、反洗钱有无问题版本均存在条件删除或改写规则。
5. 开发口径：章节编号、整改意见、履职评价、审计结论不能硬编码或全自动定稿，必须支持规则生成、自动校验和人工确认。
