# 制度的现行有效性

## 默认只看现行有效

检索工具的 `include_superseded` 默认 `false`,只返回 `effective` 的条款。
**绝大多数问题都该用这个默认值** —— 用户问「有什么规定」时想知道的是现在适用什么。

## 什么时候该放开

只有这几种情况值得传 `include_superseded: true`:

- 用户明确问「以前是怎么规定的」「哪一年修订的」「和旧版有什么区别」
- 用户引用了一条你在现行库里找不到的条款,需要确认它是否已被废止
- 要回答「这项要求是什么时候开始的」

放开之后,**必须在回答里区分现行与失效** —— 把一条 `superseded` 的条款当现行依据给出去,
比答不出来更糟。

## 怎么表述

- 现行有效:直接引用,不必特别声明
- 已被替代:「该条款已被 XX 替代,现行规定是……」——要同时给出现行版本
- 已废止:「该条款已废止,当前无对应要求」或指出替代性安排
- 拿不准:如实说「检索结果显示状态为 X」,不要替库里的数据下判断

## 一个常见误判

`version` / `effective_date` 字段为空**不代表**条款失效。判定时效性只看 `status`,
不看日期字段是否填写。
