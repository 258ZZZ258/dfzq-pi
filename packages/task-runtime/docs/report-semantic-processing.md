# 按需问题整理与归纳

## 触发与配置

配置位置：`specs/audit-report/skills/semantic-policy.json`。默认开启，问题数达到8条触发对应评价段落的抽取式归纳；已登记重大问题不受条数限制。反洗钱重大事项本身不触发分段，仍须存在明确阅读边界。以上是可调整的工程初值，不是监管规定。

默认保持原文。不按字数、句数、分号或书名号触发。仅对连续文本中多个明确编号子项创建候选作业；单一“制度＋事实”保持输入写法，不由模型逐报告随机拆段。引号中的编号不作为子项；子项的小标题和后续解释组成不可拆业务块。已有换行、“一是/二是”或独立internalSubitems的内容跳过。整理限定当前项目、当前营业部、非历史问题；needs-input底稿不执行语义整理。

## 执行契约

仍走原 RuntimeSpec→ProviderProfile→ToolsetRegistry→SessionRuntime。`generate_report_draft`先生成规则基准，若存在待办则返回`semantic-pending`及作业清单。模型通过`get_report_semantic_job`读取不可变原句或问题标题，只提交`{"groups":[["原句或问题ID"],...]}`给`submit_report_semantic_job`。不能提交改写的正文、制度、金额、来源或重要性。

- 整理：模型先判断是否必要，再选择业务块边界；可提交所有ID在同一组，成功保留原文。程序保持所有字符和原顺序，仅允许在块间换行，不允许拆开子项的小标题和事实解释。已有标题不改；没有独立policyBasis时保留空字段，制度原文仍保留在问题段落中，不伪造独立制度来源。不是对任意rawDetail自动解析全部结构化字段。
- 归纳：模型将已有问题按原业务类别分组；原评价已覆盖类别则保持原文，否则补充一句类别概括，不追加问题标题清单。全部问题必须恰好一次，不能跨类别混组，不合并问题数量、不重新认定重大或个人责任。不是开放式风险影响总结。
- 历史比对：每条有未决组合的历史问题一个compare批次，输入为该历史问题和本次全部问题。提交comparisons数组，每个本次ID恰好一次，带sameProblem、rationale、两期事实引用及identity。identity包含previousObject/currentObject/previousFailure/currentFailure（分别是两侧引用中至少4字符的具体对象和缺陷原文短语）及objectRelation/failureRelation（same/different/insufficient）。任一different必须判false；两者均same才允许true；否则作为未决拒绝。不能以公示、管理等大类替代具体对象和未履行的义务。支持多选和全部不匹配；重复、漏项、未知ID、无效引用、维度和结论矛盾均拒绝。关闭可选整理不关闭必要比对，未完成或失败仍阻断交付。
- 同一问题出现在常规正文与反洗钱附件时，复用同一整理结果，保留各自段落ID。段落来源引用不由模型提供。
- 每项最多两次提交。可选整理/归纳失败后保留规则原文，也可明确调用`retain_report_semantic_job`；retained不是整理成功。compare失败后不得交付，不能通过保留原稿绕过。新一轮运行清除作业状态。
- 可选整理/归纳作业accepted或retained、必要compare作业全部accepted后，才能交付。空白段落及内部处理状态阻断生成。独立制度字段为空时不创建空段落节点。Java输入和成功answer结构不变，无新增人工生成前确认。

## 验证

历史比较按一条历史问题批量处理本次全部问题；20条历史与30条本次最多20个批次，每批31条完整记录，不截断候选。逐对判断仍有600个，但不再需要600个模型作业；实际请求数还包含工具调用和重试，不能声称费用降低30倍。内容超出上下文或输出额度时应失败并保留未决，不得静默裁剪。完整事实及子项一致的规则确认仍保留，批次结果不能否定它。

严格评分不再调用生成器的历史匹配函数。历史结论在缺少独立评估时记为未核验（0），即使引用原文真实也不自动得分。离线独立标注通过`evaluateComparisonLabels`核验逐对0/1结果，检查误判、漏项、重复和额外结果；该标注仅用于评估，不是生产生成前的人工确认。引入这项校验后，不应继续沿用旧样本满分宣传语义准确率。

定向测试：`node ../../node_modules/vitest/dist/cli.js --run test/report-semantic.test.ts test/audit-report-agent.test.ts test/session-runtime.test.ts test/server-startup.test.ts`。

覆盖规范原文跳过、按需阈值、来源归属、原句完整性、数字和否定保留、重复/漏句/伪造ID/任意文字拒绝、来源缺失、有限重试回退、交付阻断及跨运行隔离。实际效果还需检查模型分组是否有阅读价值；合法分组不等于所有语义关系已被独立验证。

测试用固定分组仅是反例/回归断言。真实模型效果验证使用Excel和模拟HTTP取数，再调用正式运行工厂，分别保存规则基准、实际文档、逐句rubric和差异清单。测试数据和产物不入库。既有自由经营分析修订不属于这次新增的保真能力，也不能由本轮结果推断其准确率。

本地模拟脚本可显式设置`AUDIT_E2E_CAPTURE_COMPARISONS=1`保存比较作业状态和逐对结果，用于和预先制定的标签核对；默认关闭，不改变生产日志脱敏策略。维度判断仍来自模型，逻辑一致不等于语义必然正确，不能当作独立评分器。
