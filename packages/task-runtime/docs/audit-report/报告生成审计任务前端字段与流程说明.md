# 报告生成审计任务前端字段与流程说明

## 1. 文档目的

本文用于明确创建【报告生成】审计任务时的前端表单字段、后台自动补齐字段、任务处理流程及前后端职责边界，适用于以下三类报告：

- 常规审计报告
- 离任审计报告
- 反洗钱审计报告

基本原则是：用户只填写或确认任务范围，不在创建任务时手工录入报告事实、审计问题或审计结论。机构信息、人员信息、经营数据、审计发现及反洗钱数据等由后台从相应业务系统获取。

## 2. 当前实现说明

当前智能体实现中，报告任务由审计项目记录驱动。演示环境从模拟系统 Excel 的“审计项目”表读取任务，再通过审计、人力、财务、OA及反洗钱等模拟接口取数。

当前尚未提供面向前端的正式任务创建接口。生产实现建议新增：

```text
POST /api/report-tasks
```

前端提交用户选择的任务范围，后端根据审计项目和系统数据生成完整的报告任务对象。

## 3. 用户填写或确认的字段

| 字段 | 接口字段 | 是否必填 | 前端形式 | 处理说明 |
|---|---|---:|---|---|
| 审计项目 | `projectId` | 是 | 项目选择器 | 报告取数的主入口，应选择已有审计项目 |
| 报告类型 | `reportType` | 是 | 单选框或下拉框 | 可选常规审计、离任审计、反洗钱审计 |
| 被审计单位 | `organizationId` | 是 | 机构选择器 | 默认由审计项目带出；一个项目涉及多个营业部时由用户选择 |
| 审计开始日期 | `auditStart` | 是 | 日期选择器 | 默认由审计项目带出，正常情况下仅供确认 |
| 审计结束日期 | `auditEnd` | 是 | 日期选择器 | 默认由审计项目带出，正常情况下仅供确认 |
| 报告日期 | `reportDate` | 是 | 日期选择器 | 用于报告落款，可默认当天，并允许按实际出具日期调整 |
| 离任审计对象 | `subjectPersonId` | 条件必填 | 人员选择器 | 仅离任审计显示并必填，其他报告类型不传或传空 |

### 3.1 报告类型取值

| 报告类型 | 接口值 |
|---|---|
| 常规审计报告 | `regular` |
| 离任审计报告 | `turnover` |
| 反洗钱审计报告 | `aml` |

### 3.2 建议的创建任务请求

常规审计任务示例：

```json
{
  "projectId": "PRJ-QF-2025",
  "reportType": "regular",
  "organizationId": "ORG-QF-001",
  "auditStart": "2023-09-01",
  "auditEnd": "2025-10-31",
  "reportDate": "2025-12-26",
  "subjectPersonId": null
}
```

离任审计任务示例：

```json
{
  "projectId": "PRJ-QF-2025",
  "reportType": "turnover",
  "organizationId": "ORG-QF-001",
  "auditStart": "2023-09-01",
  "auditEnd": "2025-10-31",
  "reportDate": "2025-12-09",
  "subjectPersonId": "P-LUJUN"
}
```

前端提交的机构和审计期间即使由项目自动带出，后端仍应根据审计项目重新核验，不能直接信任前端传值。

## 4. 后台自动生成或补齐的字段

以下字段不要求用户填写：

| 字段 | 来源或处理方式 |
|---|---|
| 任务编号 `taskId` | 后台创建任务时生成 |
| 营业部全称、机构编码 | 机构基础库 |
| 营业地址、营业面积、机构沿革 | 机构基础库及相关权威数据源 |
| 审计组成立月份 | 审计项目或审计工作流 |
| 离任人员姓名、职务 | 人员系统、OA任免记录 |
| 任职日期、免职日期 | OA任职及免职发文推导 |
| 任免文件名称及文号 | OA任免发文 |
| 模板编号 `templateId` | 根据报告类型自动匹配 |
| 模板版本 `templateVersion` | 根据报告类型和生效日期匹配有效版本 |
| 征求意见反馈状态 | 审计项目工作流 |
| 人员数量 | 人力系统期末快照 |
| 经营指标、排名及参与家数 | 财务、经营分析或绩效数据源 |
| 审计问题和问题详情 | 审计系统 |
| 整改情况 | 审计整改记录 |
| 投诉、诉讼、问责及监管事项 | 合规、审计等相关系统 |
| 反洗钱领域事实、可疑交易及协查函 | 反洗钱相关系统 |
| 操作人、租户和数据访问范围 | 后端根据登录用户及权限注入 |

`caseId` 和 `description` 仅用于当前模拟案例及测试，不属于正式前端创建任务字段。

## 5. 前端交互流程

### 5.1 创建入口

建议支持以下两个入口：

1. 在审计项目详情页点击【生成报告】，自动带入当前审计项目。
2. 在报告任务列表点击【新建任务】，再选择审计项目。

### 5.2 表单初始化

选择审计项目后，后台返回以下默认值：

- 被审计单位
- 审计开始日期和结束日期
- 可生成的报告类型
- 审计项目工作流状态
- 可选择的离任审计对象
- 默认报告日期

前端应优先使用后台返回值，避免自行拼接机构名称或审计期间。

### 5.3 动态字段

- 选择常规审计时，不显示离任审计对象。
- 选择反洗钱审计时，不显示离任审计对象。
- 选择离任审计时，显示离任审计对象并设为必填。
- 选择离任人员后，可以展示系统查询到的职务和任职期间，但不要求用户手工填写任免日期。

### 5.4 创建校验

前端进行基础校验：

- 审计项目不能为空。
- 报告类型不能为空。
- 被审计单位不能为空。
- 审计开始日期不能晚于结束日期。
- 报告日期不能为空。
- 离任审计必须选择离任人员。

后台进行权威校验：

- 当前用户是否有权访问该审计项目和营业部。
- 审计项目、营业部和审计期间是否一致。
- 选择的报告类型是否适用于该审计项目。
- 离任人员是否属于该项目及被审计单位。
- OA系统是否存在完整的任职和免职记录。
- 对应报告模板及有效版本是否存在。
- 审计征求意见反馈流程是否完成。

## 6. 报告生成流程

### 6.1 创建任务

用户提交表单后，后台生成 `taskId`，保存任务范围、创建人、创建时间和初始状态。

### 6.2 数据获取

后台根据任务范围从各业务系统获取数据：

1. 从审计系统获取项目、审计期间、审计发现、问题详情和整改情况。
2. 从机构基础库获取营业部名称、地址、面积及机构沿革。
3. 从人力系统获取审计期末人员快照。
4. 从OA系统获取离任人员任职、免职及代为履职记录。
5. 从财务或经营数据源获取经营指标、排名和排名参与家数。
6. 从合规及相关系统获取投诉、诉讼、问责和监管事项。
7. 反洗钱报告额外获取六大领域检查结果、可疑交易、风险等级审核及协查函等数据。
8. 离任报告额外获取上一次审计项目及问题明细，用于两期问题比对。

### 6.3 数据完整性检查

系统形成证据绑定的事实数据包，并检查：

- 机构是否与任务一致。
- 人员快照是否覆盖审计期末。
- 常规和离任报告的经营数据是否完整。
- 风险事项是已确认无记录，还是尚未查询到数据。
- 离任审计任职及免职记录是否完整。
- 反洗钱六个必查领域是否全部取得结果。
- 审计问题和重大事项查询是否完整。

关键数据缺失或冲突时，系统不得自行补写，任务进入【数据待补充】状态，并向前端返回具体缺失项。

### 6.4 生成报告

数据完整后，系统按照以下方式生成：

- 固定模板内容保持原文。
- 明确字段和数值通过规则填充。
- 经营情况总结、复杂问题归纳及历次问题语义判断等必要内容由大模型处理。
- 每个可变句子绑定原始系统证据。
- 生成结构化草稿和Word报告。

### 6.5 质量检查

报告生成后执行以下检查：

- 报告章节和模板结构检查。
- 每个可变句子的事实主张核验。
- 原始系统记录及证据链核验。
- 数值、日期、人员、机构和问题数量核验。
- 中文标点、重复文字、字体和表格格式检查。

### 6.6 人工审核

质量检查通过后，任务进入【待人工审核】状态。审计人员可以查看、修改、确认、下载和归档报告。

人工审核发生在报告生成之后，不要求用户在创建任务时填写审计结论、重大问题判断或其他人工专业判断。

## 7. 征求意见反馈状态的处理

当前生成逻辑要求审计征求意见反馈流程完成后，才能生成正常的待审核报告。

前端可以采用以下方式：

- 允许用户提前创建任务。
- 若反馈流程尚未完成，任务显示为【数据待就绪】。
- 系统暂不执行正式生成，或生成 `needs-input` 状态并说明“审计征求意见反馈流程未完成”。
- 反馈流程完成后，由系统自动触发或由用户再次点击【开始生成】。

征求意见反馈状态来自审计工作流，不由用户手工勾选。

## 8. 建议的任务状态

| 状态 | 说明 | 前端可执行操作 |
|---|---|---|
| 待生成 | 任务已创建，尚未开始取数 | 开始生成、取消任务 |
| 取数中 | 正在从各业务系统获取数据 | 查看进度 |
| 数据待就绪 | 业务流程尚未完成，如征求意见反馈未完成 | 查看原因 |
| 数据待补充 | 关键数据缺失或冲突 | 查看缺失项、重新检查 |
| 生成中 | 正在形成事实包和报告草稿 | 查看进度 |
| 待人工审核 | 报告已生成并通过自动检查 | 预览、编辑、确认 |
| 已完成 | 人工审核完成 | 下载、归档 |
| 生成失败 | 发生接口、模型、模板或系统异常 | 查看错误、重新生成 |
| 已取消 | 用户取消任务 | 查看记录 |

## 9. 建议的后端接口

| 接口 | 用途 |
|---|---|
| `GET /api/audit-projects` | 查询用户可访问的审计项目 |
| `GET /api/audit-projects/{projectId}/report-options` | 获取项目默认机构、期间、可生成报告类型及离任人员 |
| `POST /api/report-tasks` | 创建报告任务 |
| `GET /api/report-tasks` | 查询报告任务列表 |
| `GET /api/report-tasks/{taskId}` | 查询任务详情、状态及缺失项 |
| `POST /api/report-tasks/{taskId}/generate` | 开始或重新生成报告 |
| `POST /api/report-tasks/{taskId}/cancel` | 取消尚未完成的任务 |
| `GET /api/report-tasks/{taskId}/report` | 获取报告草稿、证据及质量检查结果 |
| `POST /api/report-tasks/{taskId}/review` | 提交人工审核结果 |
| `GET /api/report-tasks/{taskId}/download` | 下载审核后的Word报告 |

## 10. 前后端职责边界

### 10.1 前端负责

- 展示用户有权访问的审计项目和营业部。
- 收集并校验少量任务范围字段。
- 根据报告类型动态展示离任人员字段。
- 展示任务进度、缺失数据和失败原因。
- 展示生成报告、证据来源和自动质量检查结果。
- 提供报告生成后的人工审核、确认和下载入口。

### 10.2 后端负责

- 校验权限及任务范围。
- 生成任务编号并保存任务状态。
- 从各业务系统获取权威数据。
- 自动选择有效模板和版本。
- 校验数据完整性并冻结事实数据包。
- 调用规则和大模型生成报告。
- 执行逐句事实核验和格式检查。
- 保存生成过程、数据版本、模型版本及操作记录。
- 确保人工审核只发生在报告生成之后。
