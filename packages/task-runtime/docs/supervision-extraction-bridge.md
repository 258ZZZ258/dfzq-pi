# Extraction response to analysis

The supervision toolset parser accepts `{task, snapshotAt, categoryMappings, extractionResults}`. Each extractionResults item is the complete internal audit-ai `supervision-extraction.v1` response including uploadedMaterial, evidence and facts. Do not mix this entry mode with materials/uploadedMaterials/issues/rectifications/accountabilities. The caller must retain the internal authorization and current document-version scope; this adapter is not a public evidence-upload API.

The adapter validates extracted/indexed state, unique document versions/fact IDs/evidence IDs, configured rule and source type, organization membership, and all primary/supporting quotations against the same document version. Bad identity or quotations reject the request. Required fields are recomputed from current backend rules, ignoring model-supplied confirmationStatus/missingRequiredFields. The production toolset factory additionally calls audit-ai `/v1/supervision/verify-fields` for all business fields, supplying the complete cited evidence blocks to check meaning, subjects, numbers and negation. Response IDs/booleans/coverage are validated. Rejected fields cannot auto-confirm, even if literally quoted. Model/backend failure aborts instead of accepting a partial verification. The synchronous parser is a conservative local structural/literal check, not a replacement for production semantic verification. Automatic confirmation is a program validation status, not human approval or a guarantee that an LLM cannot be mistaken.

Issue IDs derive from documentVersionId and factId. Fields remain in fieldValues and all evidence IDs are retained. Department names are not fabricated into department IDs. Severity without explicit classification is `unknown`. Category uses the version-controlled categories.json keyword evidence and the rule's allowed category list; only a single match is accepted, otherwise `未分类`. Consumers must accept the unknown severity enum.

audit-ai now extracts factType FINDING/RECTIFICATION/ACCOUNTABILITY/LITIGATION/UNSPECIFIED. Follow-up reports repeating earlier findings must be RECTIFICATION, not new findings. RECTIFICATION and ACCOUNTABILITY create independent records without requiring all finding fields, and without attaching a newly fabricated issue ID. Their empty referencedIssueIds go through cross-document semantic matching. Only a genuine FINDING with its own progress may create a direct same-fact relationship. Old UNSPECIFIED facts with progress are treated conservatively as progress records; re-extract historical ambiguous results to obtain factType. Different genuine findings are not merged merely because their text is identical. Rectification requirements alone do not establish progress. Unknown status never means COMPLETED. Unverified records are retained but not auto-associated.

Result includes rectifications/accountabilities catalogs. A verified standalone accountability decision can be counted and cited without inventing a new issue. Rectification statistics distinguish requiredTotal, unmatchedTotal, coverageRate, matchedCompletionRate and completionRate (completed / all confirmed issues requiring rectification). Missing progress is explicitly visible through coverage and unmatched counts; do not label matchedCompletionRate as overall completion.

Both scope and final-result construction apply lawsuit selection. Within the analysis period, records are grouped by selected organization and normalized exact caseNumber; each case retains its latest reportMonth (YYYY-MM or YYYY年M月). Month-only snapshots represent calendar month end: a June snapshot cannot describe a report ending June 15. The material version/date authorization filter remains in effect. Missing/invalid month or missing case number stays pending. Multiple records in the same latest month stay pending even if their text looks similar. Prior months remain in storage but do not count as new cases; input arrays are not mutated. Confirmed rectification histories, including model-confirmed item matches, likewise use the latest dated state; same-date conflicts remain unresolved.

Verification covers parser-to-statistics, completion counts, missing required fields, forged quotations, wrong versions, duplicate facts, mixed input modes, different cases/months, out-of-period months and same-month conflicts. Existing extracted results from PDF/DOCX/accountability/litigation were replayed with a test upload envelope; their missing source dates correctly prevented automatic confirmation. This replay is not a Java upload/PG/production integration test. Java must pass the full extraction response to this entry mode; no Java persistence code changes are included.
